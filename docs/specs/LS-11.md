# LS-11 — RTL layout mirroring stress-test

Issue: [LS-11](https://linear.app/brilliant-solutions/issue/LS-11). Ruleset:
`docs/rtl-mirroring-ruleset.md` (RTL-1 / LS-20) — **the authority for what flips**. This spec says
how it is built; it never restates a rule (agent-guidelines §4).

Rules are cited as **F1–F10** (flip), **N1–N8** (never flip), **G1–G4** (flag) throughout.

### §1.2 Upstream amendments this issue requires

**LS-4's snapshot primitive and LS-3's traversal are both text-only.** Every previous mutating
feature (pseudo-loc, preview) changes `characters` on a `TextNode`. RTL mirroring is the first
feature that mutates **containers** — `layoutMode`, padding, alignment, child order, constraints,
grid position. Nothing in the current primitives can see or restore any of that.

This is a real gap, not an inconvenience, and it must be fixed upstream rather than forked
(agent-guidelines §4). LS-4's own types anticipate it: `TextNodeSnapshot`'s header calls itself a
*"Closed set … a new op that writes an uncaptured property expands this in place."*

1. **`withSnapshot` must accept `SceneNode`, not only `TextNode`.**
   Today: `withSnapshot(nodes: readonly TextNode[], op, mutate: (node: TextNode) => Promise<void>)`.
   A mirror operates on frames, so it cannot call the primitive at all. Widening the parameter and
   the `mutate` callback is the minimum change; the eligibility gate and manifest logic are unaffected.

2. **The snapshot shape must cover container layout.** `TextNodeSnapshot` captures `characters`,
   `textAutoResize`, `textTruncation`, `maxLines`, `width/height`, `x/y`, `textAlignHorizontal`,
   `textAlignVertical`. A mirror additionally changes: `layoutMode`, `primaryAxisAlignItems`,
   `counterAxisAlignItems`, `paddingLeft`, `paddingRight`, `itemReverseZIndex`, child **order**,
   `layoutPositioning`, `constraints.horizontal`, and grid row/column position and
   `gridChildHorizontalAlign`. Expand to a discriminated union — `TextNodeSnapshot |
   ContainerSnapshot` on a `kind` field — rather than making every field optional on one type, so
   the restore step stays exhaustively checkable.

   **Child order is the awkward member**: it is not a property but a permutation. Capture the
   ordered `children` ids; restore by re-inserting in the recorded order.

3. **Eligibility flags are text concepts.** `EligibilityFlags` is
   `{ hasMissingFont, isMixedFont, inInstance, empty, alreadyMutated }` — the first, second and
   fourth are meaningless for a frame. `mutationBlockReason` needs a container arm; `alreadyMutated`
   and `inInstance` remain meaningful and are the two that matter here (§2.7).

4. **LS-3 must be able to collect containers.** `traverse(scope)` returns `TextNodeModel[]` and
   `collectTextNodes(scope)` returns `TextNode[]`. Neither can produce the frames a mirror walks.
   Add `collectContainers(scope): SceneNode[]` alongside `collectTextNodes`, honouring the same
   `NoSelectionError` and hidden-node rules.

**Why not work around it.** A private snapshot inside `src/main/rtl/` would fork the durability
contract: restore-on-launch (`restoreAll`) reads one manifest, and a second, parallel store would
leave mirrored files unrecoverable after a crash — precisely the failure LS-4 exists to prevent.

## §2 Resolved Defaults

### §2.1 The ruleset is the authority; this spec adds no rules

F1–F10, N1–N8 and G1–G4 are applied exactly as written in `docs/rtl-mirroring-ruleset.md`. Where
this spec appears to add a rule it is resolving an *implementation* question the ruleset
deliberately left to the spec (ordering, containment, failure handling).

### §2.2 What counts as a container

Mirrored: `FRAME`, `COMPONENT`, `COMPONENT_SET`, `INSTANCE` (with §2.7's restriction), `SECTION`,
and `GROUP`. A `GROUP` has no layout properties, so only F7 applies, about the group's own bounds
(ruleset §7.4). A `SECTION` is treated as a frame with `layoutMode === 'NONE'`.

Every other node type is a *child* to be positioned, never a container to descend into.

### §2.3 Ordering is not load-bearing, and that is a result, not an assumption

Mirroring is applied **per container, each in its own coordinate space** (ruleset E1). The obvious
worry — that reordering a parent's children invalidates a child's mirrored `x` — does not arise:

- F1 reorders children of an **auto-layout** frame. Those children are positioned *by* the layout,
  so their `x` is derived, never written.
- F7 writes `x` only for children that are **not** in an auto-layout flow — a `layoutMode === 'NONE'`
  parent, or `layoutPositioning === 'ABSOLUTE'` (ruleset E2). F1 never touches those.

The two rules therefore operate on disjoint sets, and `parentWidth` is never changed by a mirror (no
rule resizes anything). Recursion order is free. **The harness must prove this** rather than trust
it — §3.3 asserts mirror-twice is an identity, which fails loudly if the sets ever overlap.

### §2.4 Grid columns are written in two phases

F9 remaps column indices, and `setGridChildPosition` throws if a write *transiently* overlaps
another child — so assigning final indices one child at a time collides mid-sequence whenever the
permutation is not the identity.

Two-phase write: move every affected child to a free row band first (or stage it out of the grid),
then place each at its final `(row, column)`. Rows never change (F9), so the staging band is the
only extra state, and it is released before the batch returns.

### §2.5 Instances: mirror what is writable, flag what is not

Figma cannot reparent **children of instances** — the typings state a group's node list *"cannot
include any node that cannot be reparented, such as children of instances."* **F1 is therefore
impossible inside an instance**, because reversing child order is a reparent.

So for an `INSTANCE`: apply F3–F8 (its own padding, alignment, constraints — all writable
overrides), and **do not attempt F1**. Flag it under G1 so the designer knows that instance's
internal order was not mirrored. Descending into instance children is still allowed for reading.

This is the one place where the mirror is knowingly partial, and saying so in the panel is better
than a silent half-mirror.

### §2.6 Locked nodes do not block mutation

`locked` is a canvas-interaction affordance; the API writes through it, and it is inherited from
ancestors. It is **not** an eligibility gate here, which corrects the draft assumption in ruleset
G4. Asserted rather than assumed: §3.3 mirrors a locked node in the fixture and requires success.

`hasMissingFont` **does** block, for TEXT nodes only and only because F6 writes
`textAlignHorizontal` — a layout write, forbidden by CLAUDE.md's hard rule. Skip and flag.

### §2.7 Apply, revert, and no compounding

The panel's control is a `Switch` (DES-2). **On** applies, **off** reverts; there is no separate
Apply button, because unlike pseudo-loc there are no options to choose before committing.

`applyRtlMirror` **restores first, then applies**, so a second apply can never compound a mirror on
a mirror (LS-10 §2.5 precedent). LS-4's `alreadyMutated` guard is the backstop, not the mechanism.

`revertRtlMirror` calls `restoreByOp('rtl-mirror')` — never `restoreAll`, which would also revert an
active preview or pseudo-loc.

### §2.8 Undo

One `figma.commitUndo()` per apply and one per revert, matching LS-10 §2.9. A user's single Cmd-Z
undoes the whole mirror.

### §2.9 What the results list shows

The rows are the **flagged** nodes (G1, G3), not the mirrored ones — a mirror that worked needs no
row. DES-2 built seven rows with mirrored anatomy: strip on the right edge, jump chevron on the left
using `icon.16.chevron.left (local)`, text right-aligned.

Row copy names the node and why it is flagged ("icon moved — check direction", "mixed LTR/RTL text").
Counts follow LS-10's precedent: `AppliedBanner` reads `RTL mirror applied · N to check`, the
`<what is applied> · <exception count>` shape LS-10 §2.17 established as a precedent for this panel.

### §2.10 Scope, and the states

Scope is implicit: selection when non-empty, else page (ruleset §7.3). The state copy is transcribed
from DES-2's state × panel table (`docs/design.md`), including *"Nothing to mirror yet — Extract
strings first, then apply the mirror to stress-test your layout in RTL."*

A scope containing no containers yields the first-run state, not an error.

## §3 Concrete Acceptance

### §3.1 Pure unit tests — `src/main/rtl/mirror.test.ts`

`mirror.ts` takes a plain description of a node and returns the property writes to make, with no
`figma` global — so every F-rule is unit-testable (agent-guidelines §6). Enumerated cases:

- F3/F4 axis selection: `MIN`↔`MAX` on `primaryAxisAlignItems` for a **horizontal** frame and on
  `counterAxisAlignItems` for a **vertical** one, and the reverse pairing left untouched. This is
  the ruleset's named easy-to-get-wrong case.
- `CENTER`, `SPACE_BETWEEN`, `BASELINE`, `JUSTIFIED`, `STRETCH`, `SCALE` are all **unchanged**.
- F5 padding swap, including asymmetric-to-asymmetric and the symmetric no-op.
- F7 arithmetic: `x' = parentWidth − x − width`, including a child wider than its parent (negative
  result is legal and must not be clamped).
- F9 column arithmetic with `gridColumnSpan > 1`.
- **Involution**: for every rule, applying twice returns the input. Table-driven over all cases.

### §3.2 UI tests

Reducer test for the toggle's three states (off / applying / applied), and a render test in the
`ExportModal.test.ts` mould asserting the Switch, the banner and the flagged-row list mount.

### §3.3 In-Figma harness — `src/main/rtl/check.ts`

Canvas mutation and byte-identical restore are not Vitest's job (agent-guidelines §6). Driven by a
`__dev:rtl-check` sentinel, following LS-10's `check.ts` shape. Assertions:

1. **apply** — a mirror is applied; succeeded > 0.
2. **mirror-twice is identity** — apply, apply again from source, compare: proves §2.3's
   disjoint-sets claim and F-rule involution on the real runtime.
3. **revert-byte-identical** — every captured property and the full child order return to baseline.
4. **revert is op-scoped** — a pseudo-loc applied alongside survives `revertRtlMirror`.
5. **no-compounding** — a second apply mirrors from source, not from the mirrored state.
6. **grid two-phase** — a 3-column grid with a spanning child mirrors without
   `setGridChildPosition` throwing (§2.4).
7. **instance is partial and flagged** — an instance's padding mirrors, its child order does not,
   and it appears in the flagged list (§2.5).
8. **locked node mirrors** — proves §2.6 rather than assuming it.
9. **missing-font text is skipped and flagged** — F6 not applied.
10. **one-undo-step** — `figma.commitUndo` called exactly once per apply and once per revert,
    counted by wrapping it as LS-10's harness does.

### §3.4 Fixture — `fixtures/rtl-mirror.fig` (new)

No existing fixture carries the structures this needs. Built by a dev-only generator
(`src/main/devtools/generateRtlMirror.ts`) in the `extract-keys` mould, with rows for: a horizontal
auto-layout row, a vertical one, a nested pair, a wrapped (`layoutWrap`) row, a `GRID` frame with a
spanning child, an absolutely-positioned badge, a `GROUP`, an instance, a locked node, an
overlapping avatar stack (F2's z-order case), asymmetric padding, and a mixed LTR/RTL text node.

The missing-font row cannot be scripted and is completed by hand, exactly as `overflow-spike.md`
documents for its own two rows.

### §2.11 Mirroring a component master propagates to its instances

Found by the harness on the first fixture that contained a real instance.

A `COMPONENT` in scope is mirrored like any other container. Its instances then inherit that change,
so an instance's layout moves **without the mirror ever writing to it** — and the instance's own
children are `instance-locked`, meaning the panel reports them as *skipped* while the user watches
them move.

This is the LS-10 §2.7a hazard in a new place: there, mutating a master rewrote the text of every
instance that had not overridden it; here it is auto-layout state rather than characters.

**Accepted, not worked around.** Mirroring a master *should* mirror its instances — that is what a
designer would expect to see, and suppressing it would make the stress test lie about the design.
Two consequences are recorded rather than fixed:

1. **`blocked` means "we did not write it", not "it did not change".** The harness asserts the first
   (a node we mutated carries a durable snapshot) because asserting the second reported a failure
   that was not one.
2. **Revert leaves the instance carrying explicit overrides** it did not have before, since the
   restore writes values onto the instance rather than clearing an override. Property values are
   byte-identical — `revert-byte-identical` passes — but the override *state* is not. Worth a
   decision before Phase 2 if instance fidelity matters.

## §4 API pins

Reference `docs/agent-guidelines.md` §2.

**§2 must be extended by this issue.** It currently pins only `resize` /
`resizeWithoutConstraints` from this surface, which is a real gap for a feature built entirely on
auto-layout. Add, with the values verified against `@figma/plugin-typings/plugin-api.d.ts`:

- `layoutMode: 'NONE' | 'HORIZONTAL' | 'VERTICAL' | 'GRID'` — **`GRID` is newer than most
  documentation** and is not a horizontal flow.
- `primaryAxisAlignItems: 'MIN' | 'MAX' | 'CENTER' | 'SPACE_BETWEEN'`;
  `counterAxisAlignItems: 'MIN' | 'MAX' | 'CENTER' | 'BASELINE'`.
- `layoutPositioning: 'AUTO' | 'ABSOLUTE'`; `layoutWrap: 'NO_WRAP' | 'WRAP'`.
- `ConstraintType = 'MIN' | 'CENTER' | 'MAX' | 'STRETCH' | 'SCALE'`.
- `itemReverseZIndex: boolean` — and the fact that `children` order drives layout **and** paint
  order, which is why it exists.
- `gridColumnAnchorIndex` / `gridRowAnchorIndex` are **read-only**; position is written with
  `setGridChildPosition(row, col)`, which **throws on transient overlap**.
- Children of instances **cannot be reparented**.
