# LS-10 — Pseudo-localization

**Epic:** Features · **Complexity:** Low · **Blocked by:** LS-4, LS-5, LS-19, LS-24 · **Blocks:** LS-14

Transform text on canvas into a fake "translation" — padded, accented, bracketed — so layout breaks
surface before any real translation exists. Applied and reverted through LS-4's snapshot primitive,
with the three transform controls and the shared apply/revert banner designed under DES-2.

API pins: **`docs/agent-guidelines.md` §2**, and §1 for the main bundle's ES2017 floor. Conventions:
§1, §4, §6. Not repeated here.

---

## §0 Scope

**Most of this issue is already built.** `src/main/overflow/expand.ts` carries the transform, and its
header is explicit: *"The single pseudo-loc implementation in the codebase (LS-8 §1): LS-10 imports
`transform` rather than writing a second one; further options expand `PseudoLocOptions` and
`transform` in place."* `apply-pseudoloc` / `revert-pseudoloc` are already in the LS-2 message union,
`'pseudoloc'` is already a `MutationOp`, and `mutationBlockReason` already gates it.

So what this issue actually adds is: the panel, the main-thread handler, an expansion of
`PseudoLocOptions` to match the signed-off design, placeholder protection in the transform, and two
upstream amendments to LS-4 (§1.2).

**LS-10 is the first production caller of `withSnapshot`.** Today only `src/main/snapshot/check.ts`
(the LS-4 harness) and `src/main/devtools/applyBatchLeave.ts` call it. Both §1.2 amendments exist
because this issue is the first thing to put that primitive in a user's hands.

Out of scope, per the issue: persisting pseudo-loc, and exporting it.

**Not blocked by LS-23.** That issue recalibrates `LENGTH_BANDS`, which drives `expandForLanguage`
on the overflow path. Pseudo-loc uses the user-chosen `expansionPct` and never consults the bands, so
LS-23 cannot move pseudo-loc output and the two do not need sequencing.

### 1.2 Upstream amendments this issue requires

Both are LS-4's, and per §4 the fix belongs there rather than forked into this feature — LS-11 and
LS-12 need the identical behaviour and would otherwise each write a third copy.

1. **`restoreByOp(op: MutationOp): Promise<BatchResult>`.** `restoreAll()` restores *every* manifest
   entry regardless of op, but `revert-pseudoloc` is documented in the contract as reverting "all
   pseudo-loc'd nodes". Calling `restoreAll()` from Revert would also tear down an active preview or
   RTL mirror. The manifest is `Record<string, { op, capturedAt }>`, so the op is already recorded
   per node and this is a filter over data that exists — not new bookkeeping. `restoreAll()` stays as
   it is for the restore-on-launch path in `main.ts`, which *should* be op-blind.

2. **A re-apply guard in `withSnapshot`.** It writes `SNAPSHOT_KEY` unconditionally, so a second
   apply over already-mutated nodes captures the **transformed** text as the original, permanently
   losing the real one, and compounds the transform on top of itself. LS-4's spec says "idempotent"
   only of *restore* (§2, §6), never of apply, so this is a genuine gap rather than a documented
   trade-off. Nodes already carrying a snapshot should be **skipped with a `BlockReason`** so the
   existing `blocked[]` channel reports them, rather than refused with a throw — §2.11 depends on
   skip semantics.
   *Note:* `snapshot/check.ts` re-applies deliberately in places; check whether the harness needs
   adjusting alongside the guard, and do not weaken the guard to keep the harness passing.

### 1.3 Owned by LS-10 — the wire DTO expands in place

`PseudoLocOptions` currently carries `accent: boolean` and `brackets: boolean`, but DES-2 built the
controls as **selects** reading `Full accents` and `[[ ]]` — a select implies an enum, and a boolean
cannot express the built design. Its banner in `models.ts` says *"expand here, do not fork"*:

```ts
// src/common/models.ts — owned by LS-10
export type AccentStyle = 'none' | 'partial' | 'full';
export type BoundaryMarker = 'none' | 'single' | 'double';

export interface PseudoLocOptions {
	expansionPct: number;    // 30 | 40 | 50 in Phase 1; transform clamps negatives at 0
	accent: AccentStyle;     // was `accent: boolean`
	markers: BoundaryMarker; // was `brackets: boolean`
}
```

`transform` in `expand.ts` updates to consume the enums.

**The one regression risk in this issue:** `expandForLanguage` — the overflow measurement path —
shares `padToLength` with `transform`. It must keep producing byte-identical output, or LS-8's
verdicts shift and the hero feature's numbers move for reasons unrelated to LS-10. §3.1 makes that
an explicit test rather than an assumption.

## 2. Resolved Defaults

### Controls

1. **Three selects, three options each**, defaults taken from the canvas (`186:217`):

   | Control | Options | Default |
   |---|---|---|
   | Expansion | `+30%` · `+40%` · `+50%` | **+40%** |
   | Accent style | `None` · `Partial accents` · `Full accents` | **Full** |
   | Boundary markers | `None` · `[ ]` · `[[ ]]` | **`[[ ]]`** |

   The range is the Definitions doc's "commonly ~30–50%". Wider ranges were rejected: every option is
   a combination the acceptance table must cover, and DES-2 sized the cluster for compact selects.

2. **`partial` accents the five vowels** (`a e i o u` and their uppercase); **`full` is the shipped
   eight-letter map** (`a c e i n o u y`, both cases), so `full ⊃ partial`. `none` leaves characters
   alone. Accenting **never changes length** — every replacement is a single code point, which
   `expand.ts` already relies on and the expansion arithmetic assumes.

3. **Marker strings**: `single` → `[…]`, `double` → `[[ … ]]` — **with the inner spaces**, matching
   the built rows exactly (`[[ Šîgñ îñ tö yôûr àccôûñt ]]`). Markers are applied last and **do** add
   length; they sit outside the expansion target rather than counting toward it, because they are
   decoration on the string, not simulated translation growth.

4. **Control bar: the three selects plus a primary `Apply`.** The band has ~116px left after the
   selects — enough for Apply (Extract's Scan is ~60px) but not for Apply *and* a Scope select, so
   scope is implicit (§2.5). No summary bar, and no footer: `panels.tsx` registers `pseudo` with no
   Pro stub, which is LS-5 §2.2's principled absence, not an omission.

4a. **All three selects pass `prefixLabel={false}` and set `ariaLabel`.** They render bare values —
    `+40%`, `Full accents`, `[[ ]]` — whose meaning is positional, so the visible text alone does not
    say what the control does. `Dropdown` gained an `ariaLabel` prop for exactly this case; use it
    rather than falling back to `label`, which is what a screen reader would otherwise announce.

### Scope and apply

5. **Scope is selection-preferred, resolved main-side.** The UI cannot resolve it — the selection
   lives on the main thread — so `apply-pseudoloc` carries `scope: 'selection'` as the *intent* and
   main downgrades to `'page'` when `figma.currentPage.selection` is empty. Resolve by **checking
   `selection.length` first**, never by calling `collectTextNodes('selection')` and catching
   `NoSelectionError`: that exception is LS-3's signal for a user-visible empty-selection state, not
   a control-flow branch. `ScanScope` is unchanged — adding an `'auto'` member would touch LS-3,
   LS-8 and LS-9 to serve one panel.

6. **Apply is explicit.** Changing a select after applying does **not** silently re-apply; the user
   presses Apply again. A live-apply model would rewrite the user's file on every dropdown change,
   with no confirming moment for an operation that mutates their document.

7. **Re-apply restores first.** The handler calls `restoreByOp('pseudoloc')` before applying, so
   options never compound — `+40%` then `+50%` yields a 50% expansion of the *original*, not 50% of
   the already-padded text. This is why §1.2's guard skips rather than throws: after the restore
   there is nothing left to skip, and the guard exists for the paths that bypass this handler.

8. **Revert** calls `restoreByOp('pseudoloc')` and clears the applied banner.

9. **Undo** is one step per apply and one per revert — `withSnapshot` and `restoreByOp` each close
   their batch with a single `figma.commitUndo()`.

### The transform

10. **Placeholders are opaque.** `{{…}}`, `{n}`, `%@`, `%n$s` and `%s` are never accented and never
    padded inside. This is LS-6's preserve-not-generate policy applied to the canvas: accenting
    `{{count}}` into `{{çóúñt}}` makes a pseudo-loc artefact indistinguishable from a genuinely
    broken placeholder, which is precisely what this panel exists to reveal.

    Mechanics: split the source on the token grammar, transform only the literal segments, and
    reassemble with the tokens verbatim in place. The padding **target** is
    `ceil(source.length × ratio)` over the whole source — placeholder characters included, because
    they occupy real width — but the padding **material** is drawn only from literal characters.

11. **A source with no literal characters** (`"{{count}}"`) is returned with markers applied and no
    padding. There is nothing to pad with, and inventing material would mean generating a
    placeholder-like string.

11a. **The assembled padding is right-trimmed before markers are applied.** The phrase path prepends
    a space to each cycled word, so a padding run sliced to an exact deficit can end on one — which
    would put a double space inside `[[ … ]]` and read as a rendering bug rather than as padding.
    Derived while computing §3.2, not hypothetical.

11b. **Accenting runs after padding, so the padding material is the unaccented source.** Visible in
    §3.2 row 5: `Café` pads to `CaféCa` and only then accents to `ÇáféÇá`. Reversing the order would
    accent the same characters twice and change nothing, but the order is fixed so the case table is
    reproducible.

12. **Empty source** returns `''` unchanged, markers included — `transform` already does this, and an
    empty node is blocked by `mutationBlockReason` before it ever reaches the transform anyway.

13. **Deterministic throughout.** No randomness, matching `padToLength`'s existing contract: the same
    source and options always produce the same output, which is what makes §3.1 a golden-style table.

### Copy

14. **DES-2 settled the state copy** (node `544:1429`) — it is final, not owed, so LS-14 is
    implementation-only for this panel:

    | State | Headline | Body |

    | First run | Nothing to pseudo-localize yet | Select a frame or layer, then set an expansion ratio to preview how your layout holds up. |
    | No selection | Nothing selected | Select a frame or layer to pseudo-localize, or switch scope to Page. |
    | No text on page | No text layers here | This page has nothing to pseudo-localize. Try another page. |
    | Fonts unavailable | Fonts unavailable | *N* fonts could not be loaded. Affected strings will be skipped and flagged, not expanded. |
    | Operation failed | Couldn't complete | The pseudo-loc transform failed and your canvas was restored. Nothing was left changed. *[Try again]* |

15. **One DES-2 copy amendment is owed.** The *No selection* body says "or switch scope to Page",
    naming a control §2.4 does not build. Reword it — the panel already falls back to the page
    automatically, so the sentence should say so rather than point at a missing select. Recorded here
    and carried forward so the change is not lost.

16. **Banner message** is `Pseudo-loc: expansion 40%` per the canvas — the applied ratio, not the
    accent or marker settings. `AppliedState` carries the message and `onRevert`; the word "Revert"
    is LS-5's, already owned by `AppliedBanner`.

### Rows

17. Seven rows in the canvas mock are sample content, not a cap: the panel lists **every node in
    scope**, transformed string as `primary` and the LS-9 key as `meta.label` with `monoMeta`.
    Row tone is `'neutral'` with **no severity concept** — pseudo-loc is a uniform transform, not a
    per-string validation (design.md, DES-2 Deliverable 3).

18. Rows render the transform **UI-side** via the same pure `transform`, so the list shows exactly
    what the canvas holds without a round trip.

18a. **The transform moved to `src/common/pseudoloc.ts`.** It was in `src/main/overflow/expand.ts`,
    and the UI cannot import from `src/main` — `src/ui/tsconfig.json` references only `../common`,
    and pulling a main-thread module into the UI bundle is exactly what the folder map forbids. The
    alternative was a second copy, which LS-8 §1 exists to prevent. `expand.ts` keeps the
    language/band **measurement** model and imports `padToLength` from the shared module, so both
    paths still share one padding implementation. Discovered at implementation, not at spec time.

18b. **Rows come from an `extraction-request` fired as part of Apply**, and the order is
    load-bearing: extraction returns the ORIGINAL strings, which the rows transform locally. Run
    after the apply it would return already-transformed text and the rows would show a double
    transform.
    *Consequence:* a first Apply on an unstamped file costs **two undo steps**, because extraction
    stamps LS-9 keys and closes its own `commitUndo`. Subsequent applies cost one — LS-9 §2.20's
    second scan writes nothing — and the stamps are inert plugin data, so an undo that leaves them
    behind changes nothing on canvas. This is why §2.9's "one step per apply" reads as one step per
    *mutation*, not per user action.
    *There is no pre-apply row list*, and that is the built design rather than a simplification: the
    canvas carries a `Pseudo-loc Applied` shell plus empty states and nothing between them, and the
    first-run copy — "Select a frame or layer, **then set an expansion ratio** to preview…" —
    describes exactly this flow.

### 3.2 Transform case table

Transcribed to `fixtures/pseudoloc-cases.json`, as `extract-cases.json` and `export-cases.json` are:
**this table is the authority, the fixture is its transcription** (§6). Every row is `+40%` / `full`

hand-written** — including the placeholder rows, which is how §2.11a was found.

| # | source (len → target) | expected | exercises |
|---|---|---|---|
| 1 | `Settings` (8 → 12) | `[[ SéttíñgsSétt ]]` | baseline: `ceil(8 × 1.4)` = **12** |
| 2 | `Settings`, markers `none` | `SéttíñgsSétt` | marker `none` |
| 3 | `Settings`, accent `none` | `[[ SettingsSett ]]` | accent `none` |
| 4 | `Settings`, accent `partial` | `[[ SéttíngsSétt ]]` | `full ⊃ partial` — only the `ñ` differs from row 1 |
| 5 | `Café` (4 → 6) | `[[ ÇáféÇá ]]` | precomposed `é` is not an `ACCENT_MAP` key, so it survives while `C`/`a` accent; also pins §2.11b's ordering |
| 6 | `Add to cart` (11 → 16) | `[[ Ádd tó çártÁddtó ]]` | ≤20 chars ⇒ single-token padding even though it is a phrase |
| 7 | `Password must be at least 8 characters` (38 → 54) | `[[ Pásswórd múst bé át léást 8 çháráçtérs Pásswórd múst b ]]` | >20 chars ⇒ word-cycled phrase padding |
| 8 | `You have {{count}} items` (24 → 34) | `[[ Ýóú hávé {{count}} ítéms Ýóú hávé ]]` | §2.10: token verbatim, material `["You","have","items"]`, and §2.11a's trim |
| 9 | `Welcome, %1$s` (13 → 19) | `[[ Wélçómé, %1$sWélçóm ]]` | positional token protected |
| 10 | `Hello, {0}` (10 → 14) | `[[ Hélló, {0}Héll ]]` | brace-indexed token protected |
| 11 | `%1$s got 50% off` (16 → 23) | `[[ %1$s gót 50% óffgót50%ó ]]` | a bare `%` is **not** a token — it stays literal and is padding material, while `%1$s` is protected |
| 12 | `{{count}}` (9 → 13) | `[[ {{count}} ]]` | §2.11: no literal material ⇒ no padding |
| 13 | `` (empty) | `''` | §2.12 — markers are not applied to an empty source |

**Token grammar** the rows above assume: `/\{\{[^}]*\}\}|\{\d+\}|%\d+\$s|%[@s]/`. Row 11 is the one
that pins its boundaries — `%` followed by a space is not a specifier and must not be protected, or
padding material would silently shrink on any string containing a percentage.

### 3.3 In-Figma harness

Canvas mutation is not Vitest's job (§6) — a faked `figma` cannot prove a byte-identical restore.
`src/main/pseudoloc/check.ts` holds the assertions behind a dev-only button, streaming `ls10:` notes
on `progress`, exactly as LS-4's and LS-9's harnesses do.

**Fixture: `fixtures/kitchen-sink.fig`** — it already carries a missing-font row, a mixed-font row,
an empty node and text inside instances, which is the whole eligibility matrix. This harness
**mutates but does not stamp plugin keys**, so unlike LS-9 it can share the traversal fixture.

Assertions:

- Apply, then revert → every node byte-identical (characters, `textAutoResize`, width/height).
- A missing-font node is **skipped and flagged**, never mutated — the issue's second criterion.
- A multi-node selection applies across all of it — the third criterion.
- **A second Apply does not compound**: apply `+40%`, apply `+50%`, revert, and the original is back.
  This is the §1.2/§2.7 interaction and the one that would silently destroy user text if wrong.
- Cmd-Z once after an apply reverts the whole batch as one step (§2.9).

## Carried forward

- **LS-4:** the two §1.2 amendments — `restoreByOp` and the re-apply guard. Land with this issue's
  implementation, not after it; the guard closes a data-loss path.
- **DES-2 / LS-14:** the §2.15 copy amendment — the *No selection* body names a Scope control this
  panel does not build.
- **DES-2 / LS-14, second copy amendment.** A **partial** skip has nowhere to be reported: the panel
  has no summary bar, and `fonts-unavailable` only covers the case where *everything* was skipped, so
  a partial skip would just show fewer rows than the user selected, silently. The applied banner now
  carries the count — `Pseudo-loc: expansion 40% · 3 layers skipped` — which is a written string, not
  a transcribed one. Confirm or replace it.
- **LS-14, `fonts-unavailable` count.** The canvas copy says "*N* fonts could not be loaded", but
  `BlockedNode` carries a reason, not a font name, so the honest number at this layer is the count of
  *nodes* blocked for `missing-font`. Conflating them overstates whenever two nodes share a missing
  font. Either reword to layers, or have LS-4 carry the font name on the block.
- **LS-11 and LS-12** both need `restoreByOp` for the same reason LS-10 does. Once it lands they
  inherit it; if either ships before this issue, it hits the gap first.
- **The `+30/+40/+50` range is a judgement, not a measurement.** It comes from the Definitions doc's
  "commonly ~30–50%", which is the same published design-reserve guidance LS-23 found to be a poor
  per-string predictor. Pseudo-loc is a deliberate stress test rather than a prediction, so the
  reserve framing is defensible here in a way it is not for overflow — but if LS-23's real-translation
  data shows band-1 growth far from these values, revisit whether the default should be lower.
