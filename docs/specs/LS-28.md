# LS-28 — RTL Mirror panel: rows become a change summary

Issue: [LS-28](https://linear.app/brilliant-solutions/issue/LS-28). Amends the RTL Mirror panel built
by `docs/specs/LS-11.md` (§2.9, §2.10). Ruleset: `docs/rtl-mirroring-ruleset.md` — cited, never
restated.

**Why.** The panel's rows were meant to be extracted strings with their keys, carried over from
Preview and Pseudo-loc. But the mirror never touches text (N2), so those rows would read exactly the
same before and after it runs. LS-11 shipped a review list instead: the nodes the mirror moved but
could not rotate (G1). That list is useful, but it is usually empty, it never says what the mirror
actually did, and it needed an invented empty state, `nothingToReview`, for a mirror that worked
cleanly. This spec turns the rows into a **change summary**: how much was mirrored, what needs a
check, and what was skipped and why. The summary always has at least one row after an apply.

**Out of scope:** LS-29 (the leaked switch variant label and the first-run copy) and the
`Pro Stub / Sync` footer (LS-13).

### §1.2 Upstream amendment — `BlockedNode.name` (LS-4)

```ts
export interface BlockedNode {
	nodeId: string;
	reason: BlockReason;
	/** The layer's name when it was blocked (LS-28). Optional so existing producers and fixtures
	 *  stay valid; the RTL panel renders `Unnamed layer` when it is absent. */
	name?: string;
}
```

- **Producer:** `withSnapshot`'s eligibility gate (`src/main/snapshot/index.ts`, the only
  `result.blocked.push`) writes `name: node.name`. `restoreIds` never produces a `BlockedNode`, so it
  is unaffected.
- **Why upstream, not a local fork:** a skipped group needs named child rows (§2.3), and the only
  place that knows the name is the snapshot primitive. agent-guidelines §4 says to fix the upstream
  type rather than copy it locally.
- **Blast radius:** this is a read-only field on a report. Eligibility, the manifest, snapshot shape,
  mutation and restore do not change. It is still LS-4's primitive, so **the PR requires human review
  before merge** (agent-guidelines §8), and `docs/specs/LS-4.md` gets an amendment note that points
  here.
- Pseudo-loc and Preview receive the field too, and ignore it.

### §1.3 Shared-component amendment — `ResultsRow` (LS-5)

All three additions are optional. Existing call sites do not change.

```ts
export function ResultsRow(props: {
	tone: RowTone;
	primary: string;
	meta: RowMeta;
	monoMeta?: boolean;
	selected: boolean;
	onSelect: () => void;
	depth?: 0 | 1;            // 1 → left content inset 32px (--spacer-5) instead of 16px
} & RowTrailing): JSX.Element;

/** The trailing slot. A union, so a row with both a jump and a chevron does not compile. */
export type RowTrailing =
	| { onJump: () => void; jumpLabel: string; expanded?: never }   // today's rows, unchanged
	| { expanded: boolean; onJump?: never; jumpLabel?: never }      // group row: ChevronDownIcon (true) / ChevronRightIcon (false)
	| { onJump?: never; jumpLabel?: never; expanded?: never };      // no trailing affordance
```

- **`onJump` and `expanded` are mutually exclusive**, and the `RowTrailing` union enforces that at
  compile time.
- **The chevron is decorative.** The whole row is the click target (`onSelect`). The icon uses
  `icon/secondary`, the same token as the jump glyph when it is not hovered.
- **A group row is a keyboard disclosure.** When `expanded` is set, the row gets `role="button"`,
  `tabIndex={0}` and `aria-expanded`, and Enter or Space call `onSelect`. Its children are not in
  the DOM until it is opened, so without this a keyboard user could not reach skipped layers at all.
  Jump and plain rows do not change: their jump button is already the keyboard path.
- **The indent is a UI3 spacer step** (agent-guidelines §7: 0/4/8/16/24/32/40).

	| { kind: 'mirrored'; count: number }

	// …existing fields…
	mirrored: number;       // progress.completed of the last apply; 0 when not applied

	// …existing members, with `applied` widened:

export function progressAction(pending: PendingOp, blocked: readonly BlockedNode[], completed: number): RtlAction | null;

## §2 Resolved Defaults

### §2.1 Groups, order, omission

After an apply, `summarize` returns the groups in this fixed order:

1. `mirrored`. **Always present after an apply, even at 0.** A run where every layer was skipped
   still reports that 0 layers were mirrored. That is true, and it is the most useful thing the
   panel can say about that run.
2. `moved`. Present when `flagged.length > 0`.
3. `skipped` groups, one per reason that has nodes, in this order: `instance-locked`,
   `missing-font`, `already-mutated`, `empty`. This is ordered by how often a user can act on it:
   instances and fonts are fixable in the file, while the last two are side effects.

Groups with no nodes are left out. Nodes inside a group keep the order the main thread sent them in.

Before an apply, and in every other phase, `summarize` returns `[]` and the panel shows the existing
`StateView` shells.

### §2.2 Copy (`src/ui/rtl/copy.ts`)

| Group | `primary` | `meta.label` | `tone` |
|---|---|---|---|
| mirrored | `N layers mirrored` / `1 layer mirrored` | `layout flipped right-to-left` | `neutral` |
| moved | `N icons moved` / `1 icon moved` | `check direction` | `truncates` |
| skipped · `instance-locked` | `N layers skipped` / `1 layer skipped` | `inside an instance — follows its main component` | `unmeasurable` |
| skipped · `missing-font` | ″ | `font unavailable` | `unmeasurable` |
| skipped · `already-mutated` | ″ | `Preview or Pseudo-loc is active` | `unmeasurable` |
| skipped · `empty` | ″ | `empty layer` | `unmeasurable` |

- **"Layers", not "frames".** The issue's sketch says "12 frames mirrored", but `succeeded` counts
  every layer the mirror wrote to: containers, their direct children, and text layers (F6). Calling
  that number "frames" would overstate it.
- **The instance reason names what the user sees.** An instance child is skipped (the plugin never
  writes to it), but if its main component is in scope the child still moves, because LS-11 §2.11
  accepted that mirroring a main component carries over to its instances. "Inside a component
  instance" alone would put "skipped" next to a layer the user can see moving. Amended 2026-09-25
  after the first in-Figma run.
- **What counts as "moved" (amended 2026-09-25).** G1 flags an icon whose position changed.
  That covers three cases:
  - **F7:** the icon's own `x` is rewritten.
  - **F1:** its parent reverses its children. Every child moves except the middle one of an odd
    count, and absolute children are excluded.
  - **F9:** its grid column changes.

  The LS-11 build caught only F7, so an icon inside an auto-layout row was never flagged. Detection
  is `movedByParent` in `src/main/rtl/mirror.ts`. A parent-driven flag is kept only if the parent's
  own mirror succeeded.
- **"Icons"** is the user-facing word for `FLAGGABLE_TYPES` (`src/main/rtl/mirror.ts`): the leaf
  vector types, which in practice are icons. The LS-11 copy already used it.
- **Child rows:** `primary` is the node's name, falling back to `Unnamed layer` when a `BlockedNode`
  has no `name`. `meta.label` is the group's `meta.label`, and `tone` is the group's tone.
- **The banner does not change:** `appliedMessage(flagged.length)` still reads `RTL mirror applied`
  or `RTL mirror applied · N to check` (LS-10 §2.17 precedent).
- **Deleted:** `STATES.nothingToReview`, `fontsUnavailable()`, `FLAG_REASON`. The groups in the
  table above cover all three.

### §2.3 Row anatomy and behaviour

- **Standard anatomy, not mirrored.** Strip on the left, text left-aligned, trailing affordance on
  the right, the same as every other tab. The DES-2 mirrored anatomy and its bespoke
  `icon.16.chevron.left (local)` are dropped. The panel is English chrome and its content is a list
  of counts, so mirroring it would only suggest RTL content that isn't there.
- **The strip now carries meaning** (§2.2 tone column). It is no longer chrome copied from
  Overflow: amber means check this, grey means not done, neutral means done.
- **The mirrored row:** no trailing affordance, and clicking it does nothing (a no-op `onSelect`).
- **Group rows (moved and skipped):** `expanded` is set, and clicking the row dispatches
  `toggle-group`. Group rows are never `selected`.
- **Child rows:** `depth: 1`, today's jump (`select-node`) and `selected` highlighting, rendered
  directly under their open group.
- **Default expansion:** `['moved']`, reset on every apply. The group that needs a human is open,
  and the groups that are only a report start closed.

### §2.4 States (`selectShell`)

| Condition | Shell |
|---|---|
| `applying` or `reverting` | `busy` — the shared `SummaryBar`, alone (LS-30 amendment, 2026-09-25) |
| `failed` + `no-text-nodes` | `no-text-on-page` (unchanged) |
| `failed` + `no-selection` | `no-selection`: **Nothing selected**, "Select a frame or layer to mirror, or switch scope to Page." (LS-33 amendment, 2026-09-25) |
| `failed` | `operation-failed` (unchanged) |
| `applied` | `null`, which renders the summary |
| otherwise | `first-run` (unchanged) |

`no-issues` and `fonts-unavailable` are removed. The check that used to come first,
`flagged.length > 0 → null`, is removed too, because the phase alone decides the shell now.

**LS-30 amendment (2026-09-25).** As first written, `otherwise → first-run` covered `applying` and
`reverting`, so the body read "Nothing to mirror yet" for the whole of an apply or revert under a
Switch that was on and disabled. While either is in flight the body is now the shared in-flight band
and nothing else: `SummaryBar` with `tone="secondary"` and `progress="indeterminate"` (the mirror
sends no intermediate progress ticks), labelled `Applying mirror…` or `Reverting mirror…`
(`BUSY` in `copy.ts`). The `busy` check comes first, so a retry from `failed` or a re-apply after a
revert never shows the state it is leaving.

**LS-33 amendment (2026-09-25).**
- **Before:** with Selection scope and nothing selected, the mirror fell back to the whole page.
- **Now:** the main thread refuses before it touches anything, restore included
  (`resolveMirrorScope`, `src/main/rtl/scope.ts`). It answers with the existing `no-selection`
  error, and the panel shows the design's no-selection cell with Try Again.
- **Why:** scope has been explicit since ruleset §7.3, and a mirror must not restructure layout the
  user scoped out.
- **Harness:** `ls11:no-selection` asserts the refusal and that every target still matches the
  baseline.

### §2.5 LS-11 amendment

LS-11 §2.9 and the `nothingToReview` amendment in §2.10 get a one-line note: *"Superseded by
LS-28 — rows are a change summary."* They are marked, not deleted, so the history stays readable.

## §3 Concrete Acceptance

### §3.1 Unit — `src/ui/rtl/state.test.ts`

Driven from a fixed state: `mirrored: 12`, 3 flagged, blocked
`[instance-locked ×2, missing-font ×1, empty ×1]`.

1. `summarize` returns exactly
   `[mirrored(12), moved(3), skipped:instance-locked(2), skipped:missing-font(1), skipped:empty(1)]`,
   in that order. `already-mutated` is absent.
2. With 0 flagged and 0 blocked, `summarize` returns `[mirrored(12)]` and `selectShell` returns
   `null`. This replaces the old `no-issues` case.
3. The old fonts-only case (0 flagged, 1 missing-font) returns
   `[mirrored(n), skipped:missing-font(1)]` and `selectShell` returns `null`.
4. `mirrored: 0` with 2 blocked still includes `mirrored(0)` first.
5. In `idle`, `applying`, `reverting` and `failed`, `summarize` returns `[]`.
6. `apply-started` then `applied` resets `expanded` to `['moved']`. `toggle-group` adds a key and
   removes it again.
7. `progressAction('apply', blocked, 12)` yields `{ kind: 'applied', blocked, mirrored: 12 }`.

### §3.1b Unit — `src/ui/rtl/rows.test.ts`

- Row tones: `neutral`, `truncates`, `unmeasurable`.
- A collapsed group renders only its header.
- An open group renders its children directly under it, at `depth: 1`, each with a jump.
- An absent, empty or whitespace name renders `Unnamed layer`.
- Row ids stay unique when one node id appears in two groups.

### §3.2 Unit — `src/ui/rtl/copy.test.ts`

Singular and plural wording for each group, and every `SkippedReason` has a `meta.label`. The second
check is written as an exhaustive `Record<SkippedReason, string>`, so `tsc` also catches a missing
reason.

### §3.3 Unit — `src/ui/shell/ResultsRow.test.ts`

A row without `onJump` renders no jump button. `expanded: true` renders the down chevron and
`expanded: false` the right one. `depth: 1` applies the 32px inset. A row built from the current
props renders exactly as it does today.

### §3.4 In-Figma — `src/main/rtl/check.ts`

Two assertions extend the LS-11 harness on `fixtures/rtl-mirror.fig`:

- **11. blocked names:** every `BlockedNode` from the apply has a `name` equal to the live node's
  `name`. This covers the instance child (`instance-locked`) and the hand-built missing-font row.

*(An earlier draft had a 12th assertion: `succeeded.length` equals the `progress.completed` that
was sent. It was dropped during planning. The harness calls `applyRtlMirror` directly and never
sees a sent message, so the check could only compare the batch with itself. The handler sends
`completed: batch.succeeded.length` directly.)*

### §3.5 Visual (by hand, `npm run dev`)

On `fixtures/rtl-mirror.fig`, check each of the following:

- After an apply, the summary shows `N layers mirrored`, then `N icons moved`, which starts open
  with its children jumpable, then the skipped groups, which start closed.
- Each skipped group opens to named rows.
- Revert returns the panel to the first-run shell.
- Light and dark themes both render with no hex literals (agent-guidelines §7).
