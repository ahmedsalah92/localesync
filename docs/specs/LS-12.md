# LS-12 — In-canvas multi-language preview

Issue: [LS-12](https://linear.app/brilliant-solutions/issue/LS-12). Definitions: Linear doc "LS-12 —
Definitions". Design: DES-2 (LS-24), shell `186:138` "Plugin Shell — Preview Applied", Import Modal
`574:1411`, and the Preview column of the State × Panel Copy Table (`544:1407`) in file
`UlcEw6zdZzpIpxqrBz4X53`. Blockers LS-4, LS-9, LS-5, LS-19, LS-24 and LS-26 are all Done.

**What this builds.** A designer imports translations (JSON or CSV) keyed to LS-9 extraction keys.
They pick a language, and the text layers on the current page are rewritten in that language
through LS-4's snapshot primitive. They can switch language, edit a single translation inline, and
revert to the source exactly. Untranslated strings stay visibly in the source language. Keys that
match no layer are reported.

**Decided with the product owner (2026-09-25):**

| # | Decision |
|---|---|
| D1 | Imported translations persist per user in `figma.clientStorage`, keyed per file. |
| D2 | The file is identified by a random id stamped once in document-level plugin data. |
| D3 | A JSON import **always asks** for its language. CSV names its locales in its header. |
| D4 | An inline edit is **saved** to the stored translation and re-previewed on that one layer. |
| D5 | The language is switched with a **control-bar Language Select**. This is an addition to the design, recorded as a design follow-up. |
| D6 | An edit starts with a **double-click** (or Enter on a focused row). Enter or blur commits it, and Esc cancels it. |

**Out of scope** (per the issue): importing `.strings` or XML, manual full-entry mode, machine or AI
translation, team-shared translations, exporting translations or edits back out, and the
`Pro Stub / Translate` footer (LS-13).

### §1.2 Upstream amendments (LS-2, `src/common/messages.ts`)

The commands and requests below go into the compile-checked `Record` allow-lists (35b21b6). A new
type that's left out fails `tsc -b`. They also go into `messages.fixtures.ts` (one fixture per type)
and into `src/common/roundtrip.ts`'s `PROBED_COMMANDS`.

```ts
// ErrorCode gains:
	| 'no-keys'          // the page has text layers but none owns an LS-9 key: nothing extracted yet
	| 'storage-failed'   // clientStorage refused the write (5 MB cap, or cleared/unavailable)

// CHANGED — the main thread holds the translations now (D1), so the command names the language.
export interface ApplyPreview extends Envelope<'apply-preview'> {
	language: string; // canonical BCP 47, one of the stored languages
}
export type RevertPreview = Envelope<'revert-preview'>; // unchanged

// NEW commands (no RequestResponse entry; outcome on progress/error, correlated by id)
export interface PreviewImport extends Envelope<'preview-import'> {
	maps: PreviewMap[]; // one per language; each REPLACES that stored language wholesale
}
export interface PreviewEdit extends Envelope<'preview-edit'> {
	language: string;
	key: string;
	value: string | null; // null or '' deletes the translation, so the layer falls back to source
}

// NEW request → response
export type PreviewStateRequest = Envelope<'preview-state-request'>;
export interface PreviewState extends Envelope<'preview-state'> {
	languages: string[]; // stored languages for THIS file, sorted by code
}
// RequestResponse gains: 'preview-state-request': PreviewState

// NEW main → UI, sent BEFORE the terminal progress of an apply or edit (the rtl-flagged ordering)
export interface PreviewResult extends Envelope<'preview-result'> {
	language: string;
	rows: PreviewRow[];  // every key-owning text layer on the page that was not blocked, in document order
	unmatched: string[]; // keys of this language that no layer on the page owns, sorted
}
```

`scope` is deliberately absent. Preview always works on the whole current page, because LS-9 keys
are unique page-wide (rules 7 and 15).

### §1.4 Produced, main thread (`src/main/preview/`)

- `store.ts`: the translation store, pure.
  - It defines `PreviewStore { v: 1; languages: Record<string, Record<string, string>> }` and its
    pure operations `mergeImport`, `applyEdit`, `languagesOf`, `translationsFor`, `emptyStore` and
    `parseStore`, Vitest-tested. It does no `clientStorage` I/O itself.
- `persist.ts`: where a file's translations live (D1/D2). Owns both the file id and the
  `clientStorage` I/O that `store.ts` stays pure of.
  - `PREVIEW_FILE_ID_KEY = 'localesync:file-id:v1'` and `storeKeyFor(fileId)` build
    `` `localesync:preview:v1:${fileId}` ``.
  - `loadStore()` reads `figma.root.getPluginData(PREVIEW_FILE_ID_KEY)`; with no id yet, it returns
    `emptyStore()` without touching `clientStorage` — opening the panel never writes anything.
  - `saveStore(store)` stamps a new id (16 lowercase hex characters from `Math.random`, the main
    thread having no `crypto`) on first use, via `figma.root.setPluginData`, then
    `clientStorage.setAsync`. **The id is written on the first *save attempt*, even if that
    `clientStorage.setAsync` call itself then throws** — `setPluginData` is not a mutation under
    the hard-rules sense (D2, `docs/agent-guidelines.md` §2.16), so a failed save under D2 can
    still leave the id stamped; the next save reuses it rather than stamping twice. This is the
    only write Preview makes to the document outside the text layers.
- `index.ts`: `registerPreview()`, plus `applyPreview(language)` and the edit in two halves (§2.3):
  `saveEdit(language, key, value)` persists it (throwing when `clientStorage` refuses, which the
  handler maps to `storage-failed`) and `reapplyEdit(language, key, value)` rewrites the one layer
  when that language is on the canvas. The real `preview-edit` handler calls the two separately, so
  a failed save never touches the canvas; `editPreview(...)` is only the both-halves wrapper the
  in-Figma harness (`check.ts`) calls.
- `rows.ts` (pure): `ownersOf(nodes)` (rule 9: a node owns a key only when its own stamp names it),
  `planPreview(owners, translations)` (targets to write plus every row), `unmatchedKeys(owners,
  translations)`, and `withoutBlocked(rows, blocked)` (a blocked node is never a row, so it can
  never be edited). Vitest-tested.

## §2 Resolved Defaults

### §2.1 Import (UI)

1. **Entry point:** "Import ▸" in the summary bar opens the Import Modal (`574:1411`). It has
   "Choose file…" (`<input type="file" accept=".json,.csv">`), Cancel and Import. The format is
   taken from the file extension (`.json` / `.csv`, case-insensitive). Any other extension disables
   Import and shows the help line in `text/danger`.
2. **JSON language (D3):** for a `.json` file, the modal shows a **Language** text input (UI3 Text
   input), which is required and starts empty. The value must pass `canonicalLocale`. If it doesn't,
   the field shows "Not a valid language code — try de, fr-FR or pt-BR." and Import stays disabled.
   *This field is an addition to the design (§4, design follow-up).*
3. **JSON shape:**
   - The top level must be an object.
   - Nested objects are flattened with `.`: `{ "home": { "title": "…" } }` gives `home.title`.
     This is LS-6's nested i18next output.
   - A flat map with dotted keys (`{ "home.title": "…" }`) is also accepted.
   - The two forms may be mixed.
   - Every leaf must be a string. Any other leaf type (number, boolean, null, array) fails the whole
     import with the offending key: `"home.count" is not text — every value must be a string.`
   - If a key is produced twice (for example, nested and flat both give `home.title`), the import
     fails, naming the key.
4. **CSV shape** (RFC 4180):
   - A leading UTF-8 BOM is stripped, and CRLF or LF line endings are both accepted.
   - Quoted fields may contain commas, `""` escapes and line breaks.
   - The first row is the header. Exactly one column must be named `key` (compared
     case-insensitively, after trimming). Every other header cell must pass `canonicalLocale`, and
     an invalid one fails the import, naming the column.
   - Duplicate keys or duplicate locale columns fail the import.
   - Rows with fewer cells than the header are padded with empty cells. A row with more cells fails
     the import, naming its line number.
   - Fully empty lines are skipped.
   - **A row whose cells are all empty is also skipped** (final review fix), even when it has more
     cells than the header — a spreadsheet export's blank separator row (`,,`) is exactly this, and
     must not be read as a `""` key or fail as too long. A row with a blank key cell that has a
     non-empty translation cell is not a separator row, though: it fails the import with
     `Line N has a translation but no key.` (`src/ui/preview/parse.ts`'s `parseCsvTranslations`).
5. **Values are kept exactly as written: no trimming, no unescaping.** An empty value (`""`, or an
   empty CSV cell) means **no translation**. It isn't stored, and that layer falls back.
6. **Replacing a language:** if a language being imported is already stored, a confirm asks: *"French
   (fr-FR) is already imported. Importing it again replaces it, including your edits."*
   [Replace / Cancel]. The import replaces each imported language wholesale and leaves every other
   stored language untouched. **When more than one already-stored language is being replaced at
   once** (a multi-locale CSV), the confirm is plural instead: *"French (fr-FR), German (de) are
   already imported. Importing them again replaces them, including your edits."* — exactly
   `replaceNotice(codes)` (`src/ui/preview/copy.ts`), which switches on `codes.length === 1`. New
   copy not previously in this spec (§4).
7. **Sending:** the UI sends `preview-import { maps }`.
   - The main thread writes the store and answers with `progress`, and the UI then re-requests
     `preview-state`.
   - If the write fails, the answer is `error` `storage-failed`, the modal stays open showing
     *"Couldn't save these translations — LocaleSync's storage is full or unavailable."*, and nothing
     changes.
   - **If the chosen file can't be read** (the browser `File` read itself fails, before any
     parsing), the modal shows *"This file couldn't be read."* (`IMPORT.unreadable`) — new copy not
     previously in this spec (§4).
   - If the language being previewed right now is replaced, the preview is re-applied
     automatically — but not by the main thread. The main-thread `preview-import` handler only
     saves the store and answers `progress`; it never re-applies. It is the **panel** that, on a
     successful import whose maps include the active language, calls apply for that language
     itself. The net effect is still "automatically" from the user's chair.

### §2.2 Choosing a language (D5)

- **Control bar:** a 40px band holding the shared `Dropdown`, labelled "Language". Its options are
  the stored languages, shown as `languageLabel(code)` and sorted by code.
  - Before anything is imported, the band isn't rendered and the body shows the first-run state.
  - The dropdown is disabled while a preview is being applied or reverted.
- **Picking a language applies it:** the UI sends `apply-preview { language }`. There's no separate
  Apply button, the same as RTL's switch.
- **Choosing a different language** re-applies from the source, because the main thread restores
  first (§2.3). Translations never stack.
- **Revert** is the applied banner's "Revert" (`revert-preview`). The dropdown then shows no value
  ("Choose a language").
- **Banner:** "Preview: French (fr-FR)". The format is `Preview: ${languageLabel(code)}`, replacing
  the component's `Applied: [feature name]` default.
- **When the panel opens,** the UI sends `preview-state-request` and fills the dropdown from the
  answer. Nothing is applied automatically when the plugin opens: LS-4's restore-on-launch has
  already returned the canvas to its source.

### §2.3 Apply, edit and revert (main thread)

> **Amended by LS-34 §2 (2026-09-26): snapshot ownership.**
> - **Apply:** after Preview's own restore, a key-owning layer that still owns a snapshot belongs to
>   Pseudo-loc or RTL. It is reported as skipped, `already-mutated` ("Pseudo-loc or RTL is active"),
>   and is never a row, so its text is never mistaken for the source.
> - **Edit:** the direct-write path and the delete path act only on a layer whose own snapshot is
>   Preview's (`snapshotOp(node) === 'preview'`, LS-4). A Preview edit can therefore never write onto,
>   or tear down, another feature's snapshot.

**All five preview commands (`apply-preview`, `preview-edit`, `revert-preview`, `preview-import`,
`preview-state-request`) run through one main-thread serial queue** (`src/main/preview/index.ts`,
a promise-chain mutex): each runs to completion, in arrival order, before the next starts, so the
store's read-modify-write and an apply/edit's canvas window never interleave across two commands
that arrive close together.

**`applyPreview(language)`:**

1. `await figma.currentPage.loadAsync()`, then `restoreByOp('preview')`.
2. `collectTextNodes('page')`. For each layer, `readStoredKey`. The **owners** are the layers whose
   stored `n === node.id` (rule 9). Copies carrying someone else's stamp are not owners, and are
   ignored.
3. If the page has no text layers, answer `error` `no-text-nodes`. If it has text layers but no
   owners, answer `error` `no-keys`.
4. Look up `translations = store.languages[language]`. For each owner:
   - a non-empty translation makes the layer a **target** with that value;
   - otherwise the layer **falls back**: it isn't written, and its row gets `value: null`.
5. Run `withSnapshot(targets, 'preview', node => { node.characters = value })`. `withSnapshot`
   loads fonts, and its eligibility gate blocks `missing-font`, `mixed-font-char-mutation`,
   `already-mutated` (Pseudo-loc or RTL is active on the layer) and `empty`.
6. If the batch has any `failed` entry, answer `error` `mutation-failed`. The batch rolls back
   completely (LS-4).
7. Otherwise send, in this order:
   1. `preview-result { language, rows, unmatched }`:
      - `rows` covers every owner **not blocked**, in document order;
      - `source` is the layer's pre-preview text;
      - `unmatched` is the stored keys no owner holds, sorted.
   2. `error` `nodes-blocked` (a warning), with `blocked`, if anything was blocked.
   3. The terminal `progress`.
8. Keep `active = language` in memory, so an edit knows whether to re-apply.
9. `applyPreview` calls no `figma.commitUndo()` of its own — step 1's `restoreByOp` and step 5's
   `withSnapshot` each already call it once internally when they do anything. See the "Undo" note
   below §2.3's edit steps for the resulting undo-step count.

**`editPreview(language, key, value)` (D4).** §2.6's ruling R1 replaces "`restoreNode` then
`withSnapshot`" below with three separate paths, chosen so an edit stays **one** undo step (see
`src/main/preview/index.ts`'s `reapplyEdit`):

1. Update the store: `applyEdit` sets the value, or deletes it when `value` is `null` or `''`. Then
   persist it. If that fails, answer `error` `storage-failed` and change nothing.
2. If `language === active` and a layer owns `key`, one of three paths runs, keyed on the node's
   current state, not on session bookkeeping alone (a Cmd-Z between apply and edit can restore a
   node — and clear its snapshot plugin data — without the session hearing about it):
   - **Deleting the value** (`null`/`''`): `restoreNode(owner.id)` only.
   - **A new non-empty value, and the node still carries its own durable snapshot plugin data:**
     direct write — `ensureFontsLoaded(node)`, then `node.characters = value`, then one
     `figma.commitUndo()`. A missing-font throw on this path is never surfaced as `internal`; it is
     caught and the node is reported through the ordinary `nodes-blocked` channel, as a blocked
     node with reason `missing-font`, the same as any other blocked layer.
   - **A first value on a fallback node** (no snapshot to restore from): `withSnapshot([node],
     'preview', …)` only — its `already-mutated` eligibility gate is the real safety net here.
   - Either way, send a fresh `preview-result`, rebuilt for the whole page from the store (cheap:
     it only reads), then `nodes-blocked` if any, then `progress`.
3. If the language isn't active, just answer `progress`.

**`revert-preview`** runs `restoreByOp('preview')`, clears `active` and answers `progress`, or
`mutation-failed` if the restore fails. It works the same as RTL's revert.

**Undo:** `withSnapshot`, `restoreNode` and `restoreByOp` each call `figma.commitUndo()` once,
internally — this module never adds a second call on top of one of those. An apply is `restoreByOp`
+ `withSnapshot`, so it is **one** undo step when the page was already at source (nothing to
restore) and **two** when a restore actually ran, as switching languages does (§2.6 ruling R4). An
edit is exactly one of the three paths above, so it is always one step.

### §2.4 Rows and panel layout (design `186:138`)

**Layout, top to bottom:**

1. applied banner;
2. tab bar;
3. **control bar** (D5);
4. **summary bar**: `${translated} of ${rows.length} translated` on the left, "Import ▸" on the
   right;
5. rows;
6. the skipped and unmatched groups.

**Row variants,** built with `ResultsRow` and the Extract Row anatomy:

| Row | Strip (`RowTone`) | Primary text | Meta line: `label`, which may shrink with "…" | Meta line: `verdict`, which never shrinks | Trailing |
|---|---|---|---|---|---|
| Translated | `fits` (green) | the translation | key (mono) | — | jump |
| Fallback | `truncates` (amber) | the source text | key (mono) | `•  fallback — no ${languageName} translation` (warning text) | jump |
| Editing | editing tone (brand), a new `RowTone` member `'editing'` | UI3 Text input holding the current value (the source for a fallback row), fully selected | key (mono) | `•  editing` (brand text) | jump |

- `languageName` is the language part of `languageLabel` ("French").
- Putting the fallback label in `verdict` is what stops it being clipped. It's the design's open
  point: the label is fixed-width, and only the key shrinks (LS-8.2 §2.6).
- **`ResultsRow` amendment (LS-5):**
  - a new `RowTone` member `'editing'`, whose tokens are `--ls-text-brand` for both the strip and
    the meta line. `toneToken` stays exhaustive;
  - an optional `editor?: ReactNode` that replaces the primary line;
  - `onDoubleClick` on the row, which falls through when the row isn't editable.

**Editing (D6):**
- **Start:** double-click the row, or press Enter on the focused row.
- **Commit:** Enter or blur sends `preview-edit`, but only if the value changed.
- **Cancel:** Esc restores the previous value and closes the editor.
- **One at a time:** only one row can be edited at once. Starting a second commits the first.
- **No preview applied:** editing isn't available, because there's no language to edit.
- **Fallback rows are editable too,** which adds the missing translation.

**Groups** (LS-28's collapsible group rows; group state is the same pattern as `src/ui/rtl/state.ts`):
- `N keys matched no layer` (group meta: **"check your translation file"**):
  - it opens to one row per key, whose primary text is the key and whose meta is **"no layer has
    this key"**, with no jump arrow (nothing to jump to);
  - tone `unmeasurable`;
  - the group is closed by default.
- `N layers skipped`, one group per reason:
  - the reason text is `missing-font` → "font unavailable", `mixed-font-char-mutation` → "mixed
    fonts — can't rewrite", `already-mutated` → "Pseudo-loc or RTL is active" and `empty` → "empty
    layer"; this reason text is both the group's own meta and every child's meta;
  - children are named via `BlockedNode.name` (LS-28), with jump arrows;
  - tone `unmeasurable`, closed by default.

**New copy, not previously in this spec** (recorded on the design follow-up list, §4): the
unmatched group's **"check your translation file"** and its children's **"no layer has this
key"**, both above, are new — the spec's earlier drafts left the unmatched group's meta unstated.

### §2.5 States (`selectShell`, pure)

| Condition | Body |
|---|---|
| busy: loading (still awaiting the first `preview-state`), applying, reverting, or an edit in flight — busy comes first, as in LS-30 | LS-30 progress band: `Loading translations…` / `Applying French…` / `Reverting preview…` (`busyLabel`, `src/ui/preview/copy.ts`) |
| no stored languages | first run: "Nothing to preview yet" / "Import translations to preview them in place." with action "Import" |
| `failed` + `no-keys` | copy table FIRST RUN: "Nothing to preview yet" / "Extract strings first, then choose a language to preview translations in place." with Try Again |
| `failed` + `no-text-nodes` | copy table NO TEXT ON PAGE: "No text layers here" / "This page has nothing to preview. Try another page." with Try Again |
| `failed` + `mutation-failed` or `internal` | copy table OPERATION FAILED: "Couldn't complete" / "The preview failed and your canvas was restored. Nothing was left changed." with Try Again |
| `failed` + `storage-failed` (an edit's save failed — plan ruling R2, §2.6) | "Couldn't save" / "Your edit wasn't saved — LocaleSync's storage is full or unavailable." with Try Again re-applying the language |
| languages stored, none applied | "Choose a language" / "Pick a language above to preview its translations on this page." |
| applied | rows and groups |

- **No selection** is unreachable, because scope is always the page. The copy table's cell is
  recorded as N/A, the same as Pseudo-loc (design.md 2026-09-13).
- **Fonts unavailable** isn't a body state. Missing-font layers appear as a skipped group, the same
  as RTL (LS-28).
- The two rows marked as new copy ("no stored languages" and "none applied") are **new copy**, and
  go on the design follow-up list with the control bar and the language field.
- **"Your canvas was restored" is true only of an apply failure** (`mutation-failed`/`internal`
  above): the whole batch rolled back, so nothing changed on the canvas. It does not describe an
  edit's `storage-failed`, which never touched the canvas in the first place (§2.3 edit step 1) —
  hence that row's own, narrower copy.
- **A failed edit that is not `storage-failed`** (its canvas write failed, not its store save) does
  **not** land on the `mutation-failed`/`internal` row above. The panel automatically re-applies
  the current language instead — restore-then-apply converges the canvas and the panel, and if
  *that* apply then fails, its `mutation-failed`/`internal` copy is what the user sees, and it is
  true, because that failure really did restore the canvas (`onCommandError`, `src/ui/preview/state.ts`).
- **A `no-text-nodes`/`no-keys` failure clears the chosen language** (final review fix): nothing was
  previewed at all — main restores first and applies nothing for either code (§2.3 step 3) — so the
  reducer (`previewReducer`, `src/ui/preview/state.ts`) sets `language: null` on that `failed`
  action, not just `errorCode`. The control-bar dropdown then falls back to its "Choose a language"
  placeholder instead of still showing the language the user picked, which otherwise breaks a native
  `<select>`'s change event: picking that same language again fires no `onChange`, so nothing
  re-applies until the tab is remounted. Every other failure code leaves `language` alone.
- **Both of those states' own copy ("Try another page", "Extract strings first…") gets one-click
  follow-through**: their StateView now carries a "Try Again" action (`PreviewPanel.tsx`) that
  re-applies the language last attempted, held in a `lastAttempted` ref set inside `apply()` —
  needed precisely because `state.language` itself is now cleared by the bullet above, so the
  ordinary `retry` (used by the `mutation-failed`/`internal`/`storage-failed` rows) can't be reused
  as-is for these two.
- **A failed revert** (`mutation-failed` from `revert-preview`) does not move the panel to the
  `mutation-failed`/`internal` row either: the preview is still on the canvas, unreverted, so the
  panel stays on the applied banner and rows — the banner is kept precisely so its "Revert" action
  is still there to retry (`onCommandError`'s `'revert-failed'` outcome).

### §2.6 Implementation rulings (2026-09-25)

Recorded during build against `docs/superpowers/plans/2026-09-25-ls-12-preview.md`
("Plan-level rulings against the spec"), which is the binding source for all four:

- **R1** — §2.3's edit path ("`restoreNode` then `withSnapshot`") would commit undo twice, since
  both already call `figma.commitUndo()`; an edit must be one step. Resolved into the three paths
  §2.3 now describes: direct write for a value replacing one already on the canvas, `restoreNode`
  alone for a deletion, `withSnapshot` alone for a first value on a fallback node.
- **R3** — `canonicalLocale`, `languageLabel` and `languageName` live in `src/ui/preview/locale.ts`,
  not `parse.ts` as §1.5 originally had it: they're a separate concern from parsing, reused by the
  panel's own copy.
- **R4** — switching language is two undo steps, not one: `restoreByOp` commits the restore and
  `withSnapshot` commits the apply, matching Pseudo-loc today. A first apply (nothing to restore)
  stays one step, since `restoreByOp` only commits `if (anyRestored)`.

(R2 — the `storage-failed` edit-failure state — is recorded in §2.5's table directly rather than
here, since it is a spec gap being filled, not a rule overriding stated spec text.)

### §3.2 In-Figma harness (`src/main/preview/check.ts`, "Run LS-12 preview check")

**Fixture:** `fixtures/preview.fig`, built by a dev-only `generatePreview.ts` in the `extract-keys`
mould (see `fixtures/preview.md` for the authoring steps). It has keyed text layers (stamped by
running an Extract scan first) covering:
- a normal string (`preview.title`, translated in both languages);
- a string that will fall back (`preview.fallback`, translated in neither, until the edit step
  gives it its first value);
- a mixed-font layer (`preview.mixed`, two styles on one text node) that has a `de` value, so it's
  a target, and the eligibility gate blocks it `mixed-font-char-mutation`;
- a missing-font layer (`preview.missing_font`, manual, as `rtl-mirror.md` documents) that also has
  a `de` value and is blocked `missing-font`;
- an instance child, `preview › badge (instance) › inst`, keyed `preview.badge.inst` — LS-9 rule 5
  counts an instance as a frame-like ancestor, which is why its name is a key segment. Its master,
  `components › badge (component) › inst`, is keyed `components.badge.inst`, outside the `preview`
  frame, so the two `inst` layers never collide on one key. Preview is not blocked by
  `instance-locked`, so the instance child is a normal owner;
- a copy of a stamped layer (`title`'s copy, made *after* the Extract scan, so it carries the
  original's stamp and is never an owner or written). The harness makes it at run time with
  `clone()` — which carries plugin data (agent-guidelines, probe 4) — and removes it in `finally`
  (LS-34); a hand-made Cmd-D copy in the file is optional and is checked alongside it.

Import files `fixtures/preview/de.json` (LS-6's nested form) and `fixtures/preview/translations.csv`
go alongside it, each with one unmatched key (`checkout.old`) that no layer owns. The CSV's header
is `key,de,fr`. `de.json` includes a value for `preview.missing_font`, so the blocked assertion for
that layer has something to fire on. They're written from this spec's rules, not typed to match the
output — the harness re-seeds the same values in `check.ts` under a `// from fixtures/preview/*`
comment rather than reading the files, since the main thread cannot read local files.

**Assertions:**
1. **Apply `de`:**
   - every translated owner reads its German value;
   - every fallback owner is unchanged;
   - the copy is unchanged;
   - `unmatched` equals the fixture's stray key.
2. **Blocked:** the missing-font and mixed-font layers are blocked with the right reasons, and
   aren't mutated.
3. **Switch to `fr`:** every layer reads French or its source text. No German remains.
4. **Revert:** every layer is byte-identical to the baseline (the LS-4 guarantee).
5. **Edit while `de` is active:**
   - exactly one layer changes;
   - the store holds the new value;
   - deleting the value returns that layer to its source.
6. **Storage:** the store survives a `clientStorage` round trip, and the file id stays the same on a
   second call.
7. **Undo:** `commitUndo` is called once for the first apply (nothing to restore), twice for the
   switch to `fr` (restore, then apply — §2.6 ruling R4), and once per edit. The single Cmd-Z itself
   is confirmed by hand, as LS-11 does.
