# LS-34 (Part 1) — Panels keep their state across tabs; one banner row per applied feature

Issue: [LS-34](https://linear.app/brilliant-solutions/issue/LS-34) §1. The issue's other parts are
out of scope for this spec:
- **§2, the parked edge cases:** a separate bounded change.
- **§3, the design follow-ups:** drawn in Figma on 2026-09-26.
- **§4, minor polish:** a separate batch.

**Decided with the product owner (2026-09-26):**
- **Approach A:** every panel stays mounted, and the inactive ones are hidden.
- **Banner option (a):** stacked banner rows, one per applied feature.

## Why

1. **Switching tabs loses a panel's state.** `Shell.tsx` mounts only the active panel. Leaving a tab
   unmounts its panel: its reducer state and its message listeners go with it.
   - **Symptom A:** apply German in Preview, visit Overflow, come back. The panel shows "Choose a
     language" and no rows, while the banner says "Preview: German" and the canvas is German.
   - **Symptom B:** click the banner's Revert from another tab. The revert command is sent, but no
     listener is left to handle its answer, so the banner never clears. Pseudo-loc and RTL have the
     same bug.
2. **The banner has a single slot.** `AppliedState | null` is plugin-wide.
   - Apply Preview and then Pseudo-loc: the banner shows only Pseudo-loc. Preview has no Revert
     control other than the banner, so it can no longer be reverted.
   - Clearing the slot wipes whichever feature holds it: reverting Pseudo-loc also removes Preview's
     banner.

**Why this needs no main-thread change:** in production the UI iframe only reloads when the plugin
is reopened, and LS-4's restore-on-launch reverts the canvas at that point. UI state therefore never
has to outlive the iframe.

## §1 Contracts

### §1.1 Consumed, unchanged
- `PanelDef`, `PanelId`, `PANELS` (`src/ui/shell/panels.tsx`).
- `TabBar`.
- The shape of `AppliedState` (`src/ui/shell/applied.tsx`).
- Every message type in `src/common/messages.ts`: no change.

### §1.2 Amended: `src/ui/shell/tabs.ts` (LS-5)

```ts
/** Every panel, in registry order, with whether it is the visible one. Pure. The shell renders all
 *  of them and hides the rest, so no panel ever unmounts because of a tab switch (LS-34). */
export function panelVisibility<T extends { id: PanelId }>(panels: readonly T[], activeId: PanelId): { panel: T; visible: boolean }[];
```

`selectPanel` keeps its current behaviour: it still throws on an unknown id. `panelVisibility` calls
it, so an unknown `activeId` throws the same way.

### §1.3 Amended: `src/ui/shell/applied.tsx` (LS-5 §1.4)

```ts
export type AppliedFeature = 'preview' | 'pseudo' | 'rtl';
export type AppliedState = /* unchanged */
	| { kind: 'applied'; message: string; onRevert: () => void }
	| { kind: 'restored'; message: string };
export type AppliedMap = Readonly<Record<AppliedFeature, AppliedState | null>>;

/** Tab order, not apply order, so a row never moves when another feature comes or goes. */
export const BANNER_ORDER: readonly AppliedFeature[] = ['preview', 'pseudo', 'rtl'];

/** Pure. The set entries of `map`, in BANNER_ORDER. */
export function bannerRows(map: AppliedMap): { feature: AppliedFeature; state: AppliedState }[];

/** Pure. `map` with only `feature` replaced. */
export function withApplied(map: AppliedMap, feature: AppliedFeature, next: AppliedState | null): AppliedMap;

/** Scoped to one feature: setting or clearing it can never touch another feature's row. */
export function useApplied(feature: AppliedFeature): { applied: AppliedState | null; setApplied: (next: AppliedState | null) => void };

/** For the banner: every row. */
export function useAppliedRows(): { feature: AppliedFeature; state: AppliedState }[];
```

- The provider holds an `AppliedMap`, which starts with all three entries `null`.
- `setApplied` is stable across renders for a given feature. It uses a functional state update, so a
  panel's listener, registered once, can hold it safely.

## §2 Resolved Defaults

### §2.1 Shell (`src/ui/shell/Shell.tsx`)
- Render one wrapper per `panelVisibility(panels, activeId)` entry, keyed by panel id, and put the
  panel inside it.
  - **Visible wrapper:** today's column container, `flex: 1; minHeight: 0; display: flex;
    flexDirection: column`.
  - **Hidden wrapper:** the `hidden` attribute plus `display: none`. That takes it out of layout, the
    Tab order and the accessibility tree.
- Panels mount once, when the shell mounts, and stay mounted.
- Behaviour that follows from this:
  - Overflow already mounts at launch.
  - Extract, Pseudo-loc and RTL only register listeners.
  - Preview sends its one `preview-state-request`.
  - Listeners already filter messages by their own correlation ids, so a hidden panel can't act on
    another panel's traffic.
- The tab bar and `activeId` are unchanged.

### §2.2 Banner (`src/ui/shell/AppliedBanner.tsx`)
- Render one row per `useAppliedRows()` entry, stacked top to bottom in `BANNER_ORDER`.
- Each row is exactly today's 40px row: the same tokens, the same `message`, and a Revert button
  wired to that entry's `onRevert`. A `restored` entry has no button.
- Nothing is rendered when there are no rows.
- The content area below shrinks by 40px per row. There are at most three rows.

### §2.3 Panels
- **`PreviewPanel.tsx`:** `useApplied()` becomes `useApplied('preview')`.
- **`PseudoPanel.tsx`:** `useApplied()` becomes `useApplied('pseudo')`.
- **`RtlPanel.tsx`:** `useApplied()` becomes `useApplied('rtl')`.
- Nothing else in the panels changes. Their existing `setApplied(null)` calls now clear only their
  own row.

### §2.4 Docs
- **`docs/specs/LS-5.md` §1.4:** an amendment note pointing here. The sentence "Applied state is
  plugin-wide, not per-tab" becomes "per feature, not per tab".
- **`docs/design.md`:** a follow-up to draw the stacked banner, two rows, in Figma.

## §3 Concrete Acceptance

### §3.1 Vitest (`npm test`)

**`src/ui/shell/Shell.test.ts`** gains tests for `panelVisibility`:
- it returns all five panels in registry order;
- exactly one of them is visible, the active one;
- an unknown id throws.

**`src/ui/shell/applied.test.ts`** (new):
- **`withApplied`:** setting `preview` leaves `pseudo` and `rtl` unchanged; clearing `pseudo` leaves
  `preview` set; the input map is never mutated.
- **`bannerRows`:**
  - an empty map gives `[]`;
  - `pseudo` and `preview` set in that order still come out as Preview first (tab order);
  - all three set gives three rows.
- **The `restored` rule:** a type-level check that a `restored` entry still can't carry `onRevert`.

**`src/ui/shell/AppliedBanner.test.ts`** (new), rendered with `react-dom/server` inside a provider
seeded through a test-only initial map, or an equivalent:
- two applied entries render two rows, each with its own "Revert";
- a `restored` entry renders no button.

### §3.2 In Figma, by hand (`npm run dev`)
1. Preview: import `fixtures/preview/de.json` as `de` and apply German. Visit Overflow, then come
   back to Preview: the rows and the "N of M translated" count are still there.
2. From the Overflow tab, click the banner's Revert: the canvas reverts and the Preview row
   disappears.
3. Apply Preview, then Pseudo-loc: two banner rows, Preview on top. Revert Pseudo-loc: only its row
   goes, and Preview is still applied and still has its Revert. Then revert Preview.
4. Repeat step 3 with RTL: three rows are possible, and each Revert affects only its own feature.
5. The panel's scroll position and any open group survive a tab switch.
